# Chat, date routes, map search and sound settings

Chat supports touch-hold, right-click and a keyboard-focusable options button. The action sheet offers copying, author-only editing and deletion controls. Normal photos offer the native file share sheet where supported (including Save Image/Save to Files choices supplied by the phone), with a download fallback. Limited-view photos never expose MONO's save/share control. A browser cannot block screenshots or screen recording.

PDF, text, Office and OpenDocument attachments are limited to 2 MiB per document and share the existing 25 MiB couple attachment allowance. Both the file bytes and filename/size metadata are encrypted on the sender's device with the existing chat key and distinct authenticated contexts. The server stores an additional encryption-at-rest layer. Documents download as files rather than rendering arbitrary content inline. Sender/nonce idempotency, membership checks, deletion and storage accounting apply to documents too.

The chat key is remembered in this browser's IndexedDB; users do not enter a recovery code on each visit. MONO still uses the privately kept recovery code for another device or cleared storage. This is not WhatsApp's Signal protocol or a passkey recovery implementation.

Personal profile settings accept one optional ringtone per account. The admin panel can publish one background song for signed-in MONO users. Uploads accept MP3, M4A, WAV or Ogg containers up to 2 MiB, verified by their headers; actual codec support depends on the browser. Files and filenames use the server-managed private-data codec. Personal streams are account-scoped; only verified, currently authorized admins can publish the shared track. Byte-range responses support phone media playback. Account deletion removes the personal audio record.

Background music starts disabled with a default volume of 20%; playback/mute/volume are individually controlled and persisted. Web Audio gain supports devices that ignore HTML audio volume. Calls pause music and suspend its audio context; music does not replace microphone or remote-call tracks. Browser autoplay rules can still require a tap. Shared music controls are in the app header, chat sound settings and personal profile. This implementation adds no paid service, though database and hosting free-tier limits still apply.

The new date planner is a single-screen route with numbered stops. A venue can be chosen first; each stop has its own venue and start/end time. Presets and a custom stop field build routes such as Café → Arcade → Movie → Hotel. Arrange times adds 15-minute gaps. Optional name, notes and budget are collapsed. Venue selection is planning, not an actual booking. No date or selected place is created in the database until Save draft or Save date; the local unfinished draft remains on the device. Editing a field or adding a stop with Enter does not save a date.

Leaflet 1.9.4 is loaded only when the map opens. The map appears in the shared venue finder, including each date stop. Users can search city/area/landmark candidates, request device location, tap/drag the pin or use the map centre with the keyboard, then choose a 1–100 km radius. The circle and subsequent venue query use the same centre/radius. No default city or device permission is assumed. Location search accepts malls; the common “Guar City Mall” spelling is normalized to “Gaur City Mall”. Public Photon/OSM coverage may still omit venues or photos. Map tiles retain attribution and normal browser caching; no offline tile harvesting occurs.

Deployment requires the additive chat/audio migration alongside the admin/privacy migrations and the existing saved-photo crop migration. Configure the protected `DATA_ENCRYPTION_KEY` before deployment, deploy the encryption-aware version, then follow the existing private-data audit/backfill procedure. This update preserves published iPhone keyboard and saved-photo crop behavior.
