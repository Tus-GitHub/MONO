# Live call verification — 14 November 2026

Scope: existing disposable QA run d8e38499 in Chrome Incognito and Edge InPrivate,
against https://mono-kappa-beryl.vercel.app. These are two users on one Windows computer,
not two physical devices or different networks. No real-user conversations were used.

## Findings and fixes

- Caller microphone capture succeeded. Receiver displayed **Incoming voice call** with
  Answer call and Decline controls. Automatic ringtone was blocked in Edge; Play ringtone
  appeared. Actual speaker output is not established by a playback promise.
- An unanswered call hit the 40-second WebRTC timeout and misleadingly reported a network
  failure. Ringing now has its own deadline; the connection budget begins after acceptance.
  Missed/declined outcomes use neutral notices. Failed accepted connections still report
  connection failure, rather than masking genuine transport problems.
- Added green pickup and red decline/end controls with handset icons and visible labels.
- Sound setup previews the supplied song from a user gesture and preserves the audio element
  for subsequent calls. Rejected playback can retry on a trusted interaction. All call exit
  controls stop sound immediately. Playback races and preview timers are guarded.
- Incoming status polling continues in background tabs. A suspended/closed browser cannot
  be guaranteed to ring; this does not add native incoming-call or push-call support.
